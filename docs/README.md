# Numa documentation

Numa's documentation is kept beside the implementation and uses relative links
so component pages can be read independently or reused as source content for a
future documentation product.

## Using the design system

1. Browse the [component catalog](../components/README.md), then its
   [Atoms](../components/atoms/README.md) or
   [Molecules](../components/molecules/README.md) index.
2. Read the component-local README for its purpose, supported API, examples,
   semantics, Foundation integration, and known limits.
3. Use the [live showcase index](../components/showcase.html) to open the
   React/Vite previews. The examples demonstrate implemented behavior; they do
   not replace the API documentation.
4. Read [Foundation](foundation/README.md) for shared definitions and
   implemented integrations.

## Contributing

- Start with [Copilot repository instructions](../.github/copilot-instructions.md)
  and the [Numa Components skill](../.github/skills/numa-components/SKILL.md).
- Read [architecture decision records](decisions/README.md) for the status and
  rationale of historical decisions.
- Follow the repository's [testing and verification conventions](testing.md).
- Use [demos](../demos/README.md) only for exploratory work, not as evidence
  that a parameter or composition is part of a component's supported API.

The final documentation site technology is intentionally undecided. Current
README, TSX, CSS, and HTML files remain the source content and examples.
